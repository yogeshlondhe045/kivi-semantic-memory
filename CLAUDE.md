# CLAUDE.md — UCO warehouse digital twin

ROS 2 Jazzy + Gazebo Harmonic + Nav2 digital twin of an automated used-cooking-oil warehouse
(receiving, weighing, inspection, storage, AGV transport, SQLite WMS, safety, faults, dashboard).
Start with `README.md`; full operating guide in `docs/user_manual.md`.

## Platform

Ubuntu 24.04 (native or WSL2), x86_64, ≥ 4 CPU cores, ~8 GB RAM. A GPU is optional. macOS and
Windows-native are not supported. All scripts are bash and must be run from the repository root.

## Setup, step by step

1. Check what is already installed (read-only, safe to run any time):
   `./scripts/check_environment.sh`
2. Install ROS 2 Jazzy + Gazebo Harmonic + Nav2 if missing. Both commands need the user's
   approval (sudo / large downloads); ask before running them.
   - `./scripts/install_environment.sh apt`: official Ubuntu packages under `/opt/ros/jazzy`.
     This is the normal choice.
   - `./scripts/install_environment.sh robostack`: conda build. This is the route the project was
     developed and verified with. It writes `env/ros_env.sh`. Its defaults (`/opt/mm`,
     `/opt/conda-root`) need write access to `/opt`. Without root, override them:
     `MM_DIR=$HOME/.local/mm MAMBA_ROOT_PREFIX=$HOME/.local/conda-root ./scripts/install_environment.sh robostack`
     and install `xvfb` and the Mesa packages with apt only if the machine has no display.
3. Build: `./scripts/build.sh` (colcon, `--symlink-install`, output in `ros2_ws/install`).
4. Unit and ROS integration tests, no Gazebo: `./scripts/test.sh`. Expect
   `119 tests, 0 errors, 0 failures` (116 real test cases plus 3 CTest wrapper entries).

`scripts/env.sh` is sourced by every script. It finds ROS (`/opt/ros/jazzy` first, then
`env/ros_env.sh`), sources the workspace overlay, sets `ROS_DOMAIN_ID=42` and, only when
`$DISPLAY` is empty, starts `Xvfb :99` with software OpenGL. For manual `ros2` commands, run
`source scripts/env.sh` in that shell first.

## Running

| Goal | Command | Notes |
|---|---|---|
| Full demo (GUI) | `./scripts/run_demo.sh` | Gazebo + RViz2 + dashboard at http://localhost:8080 |
| Full demo (no display) | `./scripts/run_demo.sh --headless` | about 10 min; prints `DEMO PASSED` and the results path |
| Fault / safety suite | `./scripts/run_sim_tests.sh` | about 15 min; expect `PASSED 38/38` |
| Interactive stack | `source scripts/env.sh && ros2 launch uco_bringup warehouse.launch.py` | then use the commands in README "Interactive use" |
| Stop everything | `./scripts/stop_all.sh` | always run this after an interrupted run |

These runs take 10–15 minutes. When running one from Claude Code, start it as a background
command and redirect output to a log file. Watch the log for `[SCENARIO] ... PASS|FAIL` lines and
the final `DEMO PASSED|FAILED`. Do not use foreground `sleep` loops.

Results go to `runtime/results/<run>/`: `metrics.json`, CSVs, `scenario_report.json` and
`figures/*.png` (plots are generated by `scripts/plot_results.py` at the end of a run).
`runtime/` is git-ignored. To refresh report chapters 14–16 from new runs:
`python3 scripts/build_report.py --fault-run runtime/results/<fault_run> --demo-run runtime/results/<demo_run>`.

## Rules when working in this repo

- **Single source of truth:** `ros2_ws/src/uco_common/config/warehouse_layout.yaml`. After
  editing it, regenerate the world, map and keepout mask with
  `python3 ros2_ws/src/uco_simulation/scripts/generate_world.py` and rebuild. The
  `uco_simulation` tests fail if the generated files are stale.
- **Process cleanup:** always `./scripts/stop_all.sh` before starting a new simulation by hand.
  A leftover `gz sim` server survives Ctrl-C and corrupts the next run. The run scripts already
  do this and use a private `GZ_PARTITION`.
- **Python nodes:** use rclpy's single-threaded executor (the multi-threaded one costs ~5× CPU).
  Testable logic goes in `*_core.py` / `store.py` / `*_model.py`, with tests under each
  package's `test/`.
- **Toolchain pins (RoboStack):** keep `pytest<9` and `setuptools<80`. Newer versions break
  colcon test and `--symlink-install`.
- **Honest reporting:** report only test and run results that were actually produced. Point to
  the result files.

## Troubleshooting

- `ROS 2 Jazzy not found`: step 2 was not done, or `env/ros_env.sh` is missing for RoboStack.
- Gazebo crashes with EGL / ogre2 errors: unset `DISPLAY` so env.sh uses Xvfb with software
  rendering, or check the GPU driver.
- Real-time factor well below 1 or Nav2 timeouts: look for orphaned processes
  (`./scripts/stop_all.sh`) and close other CPU-heavy programs.
- Port 8080 in use: another dashboard is still running. Run `./scripts/stop_all.sh`.
- More detail: `docs/environment.md`, `docs/user_manual.md` (troubleshooting) and
  `docs/development_log.md` (every problem met during development and its fix).
